# 02 业务逻辑设计

本文档描述系统的领域概念与四大分析能力的具体判定逻辑，是领域层（`internal/domain`）实现的依据。

## 1. 领域概念

### 1.1 规则（Rule）

一条访问规则的统一模型：

```
Rule {
  ID          string        // 规则 ID（导入时指定或自动生成）
  PolicySet   string        // 归属策略集（如 fw-office / sg-prod）
  Priority    int           // 优先级，数值越小优先级越高（1 最高）
  Action      allow|deny    // 动作
  Src         CIDR 或 IP    // 源地址（支持单 IP 归一化为 /32）
  Dst         CIDR 或 IP    // 目的地址
  Protocol    tcp|udp|icmp|any
  Port        Range         // 端口范围（1-65535；协议非 TCP/UDP 时忽略）
  Description string        // 描述（审计要求）
  Source      string        // 来源（导入文件名/设备名）
  CreatedAt / UpdatedAt     // 时间戳
}
```

约束：
- 单 IP 统一归一化为 CIDR（`10.0.0.1` → `10.0.0.1/32`），保证比较可计算；
- 通配地址用 `0.0.0.0/0` 表示；通配端口用 `1-65535` 表示；
- 优先级必须 ≥ 1；动作仅 `allow` / `deny`；
- 同一策略集内允许优先级相同（由分析层按"动作合并规则"处理，见 2.3）。

### 1.2 匹配关系（Match）

规则 r 与一个流量五元组（src, dst, protocol, port）的匹配判定：

```
match(r, t) =
    r.Src.Contains(t.src)
 && r.Dst.Contains(t.dst)
 && (r.Protocol == any || r.Protocol == t.protocol)
 && (r.Port.Contains(t.port) || 非端口协议)
```

两条规则的条件重叠判定（`overlap(r1, r2)`）按四维空间求交：
- 地址维度用 CIDR 集合运算（`Intersect` / `Contains` / `Disjoint`）；
- 协议维度：`any` 与任何协议相交；同协议相交；不同具体协议不相交；
- 端口维度：区间求交；任一为通配则等于另一方。

由此得出三个关系：**相等（Equal）**、**包含（Contains）**、**相交（Intersect）**、**不相交（Disjoint）**。所有分析均建立在这组关系之上。

### 1.3 动作语义（默认策略）

系统支持两种"默认策略"，决定未命中任何规则时的动作：

| 默认策略 | 含义 | 对分析的影响 |
| --- | --- | --- |
| `default-deny`（默认） | 未匹配规则 → 拒绝 | 冗余检测中"被遮蔽的 deny 规则"无意义；冲突更敏感 |
| `default-allow` | 未匹配规则 → 允许 | 冗余检测中"被遮蔽的 allow 规则"无意义 |

默认策略是全局配置项（`config.DefaultAction`），可在启动时指定、导入时可覆盖。

### 1.4 规则生效（有效规则链）

对任意流量点 t，按优先级从高到低遍历所有规则，**第一条匹配的规则**决定动作：

```
effective(t) = first( match(r, t) for r in rules sorted by (Priority asc, ID asc) )
```

若没有任何规则匹配，则结果为 `default`（由默认策略决定）。

## 2. 四大分析逻辑

### 2.1 覆盖分析（CoverageService）

**输入**：规则子集 R（默认全部）、目标空间 T（默认自动推导）。
**目标空间推导**：取 R 中所有 Dst 的并集作为"应管控的目的空间"；也可由请求显式指定 CIDR 列表。

**步骤**：
1. 将 T 拆分为互不相交的 CIDR 前缀集合（前缀树合并，最大 32 层）；
2. 对每个前缀块 p：计算被 R 中至少一条规则**命中**的"条件空间"（协议 × 端口 组合），因为地址块可能被部分覆盖（如规则只放行 tcp/80 到 p 的子网）；
3. 汇总：
   - **覆盖度** = 被命中空间 / 目标空间（按"地址字节数 × 协议数 × 端口数"加权，简化时按地址前缀长度占比估算）；
   - **未覆盖区域**：地址块级别输出"完全未命中"的 CIDR 列表，并给出其中"部分未覆盖"的说明；
   - **覆盖冗余度**：命中数 ≥ 2 的地址块占比（说明规则重叠程度）。

**输出**：`CoverageResult{ CoverageRatio, TotalSpace, CoveredSpace, Uncovered []CIDRBlock, RedundantRatio, PerPolicySet []Stat }`。

**边界**：默认策略为 `default-allow` 时，覆盖分析仍以"是否有明确规则"为口径（规则是管控声明，与默认放行语义分开解释），结果中标注 `defaultAction` 供前端提示。

### 2.2 冲突检测（ConflictService）

**输入**：规则子集 R、动作语义（默认策略）。
**冲突定义**：两条规则条件空间**相交**且**动作不同**，则存在冲突。

**三级冲突分类**（按严重程度）：

| 级别 | 名称 | 判定 | 风险 |
| --- | --- | --- | --- |
| CRITICAL | 完全冲突 | `Equal(cond)` 且动作相反 | 同流量出现矛盾定义，结果完全取决于排序 |
| HIGH | 部分冲突 | `Intersect(cond)`（非包含）且动作相反 | 交叉区间内动作不确定 |
| MEDIUM | 优先级冲突 | `Contains(cond)`（一方包含另一方）且动作相反 | 高优先级规则遮蔽低优先级规则，被遮蔽规则"永远不生效"，可能是配置失误 |

**步骤**：
1. 规则按 (PolicySet, Priority) 分组（跨策略集规则默认不互相比较，因为不同设备语义独立；可配置 `crossPolicy=true` 开启全局比较）；
2. 组内两两比较，按上表分类；
3. 输出冲突对：`{RuleA, RuleB, Level, OverlapCond（重叠条件描述）, Suggestion}`。

**建议生成规则**：
- 完全冲突：删除其中一条，或统一动作；
- 部分冲突：确认意图后在重叠区间补一条高优先级规则；
- 优先级冲突：确认被遮蔽规则是否仍需存在，若需要则提高其优先级或收窄条件。

**复杂度**：O(n²) 两两比较；n ≤ 10,000 时走异步任务。

### 2.3 冗余检测（RedundancyService）

**输入**：规则子集 R、默认策略。
**冗余定义**：规则 r 是冗余的，当且仅当"删除 r 后，任意流量的生效动作不变"。

**推导性判定**（不枚举流量，基于条件关系）：

| 类型 | 判定条件 | 说明 |
| --- | --- | --- |
| 完全重复 | 存在 r'：`Equal(cond)` 且动作相同，且 r' 优先级不劣于 r（同优先级取 ID 小者保留） | 两条一模一样，删一条 |
| 被遮蔽 Shadowed | 存在 r'：`Contains(cond)`、动作相同、优先级更高（或同优先级 ID 更小） | r 永远不会被命中 |
| 被泛化 Generalized | 存在 r'：`Contains(cond)`、动作相同、优先级更低，但 r 的命中空间被 r' 与"更高优先级规则"联合覆盖 | 需要结合有效规则链判定：若对 r 的命中空间逐块计算 effective() 均等于 r 的动作，则 r 冗余 |

**简化实现策略**（控制代码量）：
1. 先做 O(n²) 的 Equal / Contains 扫描，收集"完全重复"与"被遮蔽"；
2. 对剩余规则，取其命中空间与更高优先级规则的差集，若差集为空则判定"被泛化"；
3. 输出冗余规则列表：`{Rule, Type, RedundantAgainst, Reason}`，以及**冗余率** = 冗余条数 / 总条数。

**说明**：被判定冗余的规则**不自动删除**，仅给出建议；前端提供"一键生成删除建议清单"。

### 2.4 目标可达性分析（ReachabilityService）

**输入**：场景集合 S（每个场景 = {src, dst, protocol, port}）、规则子集 R、默认策略。
**单场景判定**：
1. 按 (Priority, ID) 排序 R；
2. 遍历，收集所有 `match(r, t)` 的规则 → **命中规则链**（有序）；
3. 第一条命中的动作即最终动作；
4. 无命中 → 默认策略动作。

**输出**：`ReachabilityResult{ Scenario, Verdict: allow|deny|default, MatchedChain []RuleHit, Explanation 文案 }`。

**批量矩阵**：M 个源 × N 个目标 × K 个端口 = M×N×K 个场景，全部走异步任务；结果按矩阵形式组织，支持局部更新（按源分片计算后合并）。

**派生能力**：
- **变更影响分析（E1）**：对"当前规则集 + 模拟变更"构建影子规则集，对一组基线场景重新计算，diff 出 Verdict 变化的场景列表；
- **模拟执行（E6）**：影子规则集仅存内存，场景查询走同一 ReachabilityService 实例，不落库。

## 3. 规则集版本与结果快照

- 每次导入（全量替换模式）或规则增删，`ruleset_version` 自增；
- 分析任务在**提交时刻**记录 `rulesetVersion`；
- 结果表中保存 `rulesetVersion` 与必要快照（命中规则 ID 列表、统计值），保证结果可追溯；
- 完整检查会比对"结果.rulesetVersion 是否等于当前版本"，不一致时标记为"过期结果"（stale）。

## 4. 任务生命周期（业务视角）

```
            提交(API)              Worker 领取              Worker 完成
  ──pending──────▶ running ────────────────▶ success
                        │                        │
                        │ 重试(≤2次)              │ 失败
                        ▼                        ▼
                     running(重试)            failed
  （服务重启时 running → failed(interrupted)，可重新提交）
```

- 任务类型：`coverage | conflicts | redundancy | reachability | matrix | whatif | simulate`；
- 任务包含：参数（规则子集、目标空间、场景等，JSON 序列化）、创建时间、开始/结束时间、错误信息、结果引用；
- 幂等：相同参数的任务允许重复提交（各自独立执行），结果按 taskId 区分。

## 5. 关键业务规则汇总

| # | 规则 | 说明 |
| --- | --- | --- |
| BR-1 | 单 IP 归一化为 /32 后参与计算 | 保证 CIDR 关系运算正确 |
| BR-2 | 优先级数值越小越优先 | 全局一致语义 |
| BR-3 | 默认策略 default-deny | 未命中即拒绝 |
| BR-4 | 同一流量命中多条规则时，取第一条 | 即"最高优先级规则生效" |
| BR-5 | 冗余检测不自动删规则 | 只出建议 |
| BR-6 | 跨策略集默认不比较 | 不同设备语义独立，可配置开启 |
| BR-7 | 分析结果绑定 rulesetVersion | 结果可追溯、可判定过期 |
| BR-8 | 导入事务性 | 整批成功或整批失败 |
| BR-9 | 运行中任务不因规则变更而中断 | 任务基于提交时的规则子集快照执行 |
| BR-10 | 端口维度仅对 TCP/UDP 有意义 | ICMP/其他协议忽略端口匹配 |
