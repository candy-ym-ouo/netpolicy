# 01 项目概述与功能设计

## 1. 项目背景

大型企业网络（数据中心、云上 VPC、办公园区）由防火墙、交换机 ACL、云安全组、负载均衡白名单等多种设备共同管控流量。这些访问规则的现状通常是：

- **分散管理**：规则分散在多个设备、多个团队、多份表格里，缺少统一的全局视图；
- **手工维护**：规则变更靠人工评审，容易引入冲突或冗余；
- **事故频发**：新规则上线后才发现与旧规则冲突、或某个关键区域根本没有规则覆盖（隐式拒绝导致业务中断）；
- **合规压力**：等保、ISO 27001 等要求"最小权限"与定期规则审计，手工审计成本极高。

本项目提供一个**网络策略验证器**：将分散的访问规则导入统一模型，自动识别**覆盖、冲突、冗余**三类规则质量问题，并提供**目标可达性**查询，帮助运维在变更前评估影响、在审计时快速出报告。

## 2. 项目目标

1. 提供一套可导入、可迁移的**统一规则模型**（源、目的、协议、端口、动作、优先级、归属策略集）。
2. 实现四大分析能力：**覆盖分析、冲突检测、冗余检测、目标可达性分析**。
3. 分析能力可**同步执行**（小规模）也可**异步执行**（后台计算任务，大规模场景）。
4. 提供 **RESTful API** 与**简单前端**，覆盖导入、管理、分析、任务、导出全流程。
5. 提供**完整检查**：启动自检、按需检查、完整性报告。
6. 代码分层（解析/领域/存储），数据可迁移，满足代码量 2000–2200 行（不含测试）、文件数 20–25 个的工程约束。

## 3. 用户角色

| 角色 | 职责 | 典型操作 |
| --- | --- | --- |
| 网络运维工程师 | 日常规则管理、变更执行 | 导入规则、查询可达性、修复冲突 |
| 安全审计人员 | 合规审计、规则瘦身 | 运行冗余检测、导出审计报告 |
| 架构/评审人员 | 变更评审 | 变更前覆盖分析、影响面评估 |

系统**单机部署、不做多用户权限体系**（登录鉴权不在本期范围，接口预留 `X-User` 头用于审计日志记录操作人），以控制代码规模。

## 4. 功能清单

### 4.1 基础功能（必做）

#### F1 规则导入与解析
- 支持 **CSV / JSON / YAML** 三种格式的规则文件导入；
- **格式自动探测**（按文件头/内容特征识别），也可显式指定；
- 逐条解析并做**格式校验**：必填字段、IP/CIDR 合法性、端口范围、动作枚举、优先级范围；
- 导入结果为事务性：整批成功或整批失败（含错误明细定位到行号/字段）；
- 支持**追加导入**与**全量替换**两种模式。

#### F2 规则管理
- 规则列表（分页、按来源/动作/策略集/关键字过滤）；
- 单条规则详情与删除；
- 规则集导出（JSON），用于备份与迁移。

#### F3 覆盖分析（Coverage）
- 以"应管控目标空间"（默认由导入时的 `target_space` 配置或全部规则的目的集合推导）为基准，计算：
  - **覆盖度**：被至少一条规则匹配的空间占比；
  - **未覆盖区域**：按 CIDR 前缀折叠输出"空白区间"列表；
  - **覆盖冗余度**：同一区域被多条规则重复命中的程度。
- 结果支持按策略集维度拆分（每个策略集的覆盖情况）。

#### F4 冲突检测（Conflict）
- 在**同一动作语义**（默认拒绝 / 默认允许）下检测：
  - **完全冲突**：匹配条件完全相同、动作相反；
  - **部分冲突**：匹配条件交叉、动作相反，交叉区间内动作不确定；
  - **优先级冲突**：条件重叠且动作相反，最终生效动作取决于优先级，提示风险；
- 输出冲突对列表：涉及规则、重叠区间、建议动作。

#### F5 冗余检测（Redundancy）
- **完全重复**：与另一条规则完全一致（可删除其一）；
- **被遮蔽**（Shadowed）：被更高优先级规则完全包含且动作相同——永远不会被命中；
- **被泛化**（Generalized）：被另一条更宽泛规则覆盖且动作相同；
- 输出冗余规则列表与**可安全删除**建议、冗余率统计。

#### F6 目标可达性分析（Reachability）
- 输入场景：源（IP/CIDR/组）、目的（IP/CIDR/组）、协议、端口；
- 输出：**可达 / 不可达 / 部分可达**，以及**命中规则链**（按优先级从高到低列出每条匹配规则）；
- 支持**批量场景矩阵**（多源 × 多目标 × 端口）异步计算。

#### F7 后台计算（异步任务）
- 分析类型：coverage / conflicts / redundancy / reachability / matrix；
- 任务生命周期：`pending → running → success | failed | canceled`；
- Worker 池并发执行、结果持久化、失败重试、前端轮询。

#### F8 完整检查
- **启动自检**：配置、存储连接、迁移版本、迁移完整性；
- **按需检查**（`/api/v1/checks`）：
  - 规则格式完整性（持久化数据与导入校验一致）；
  - 引用完整性（策略集引用、任务引用、结果引用）；
  - 数据一致性（重复主键、空字段、孤儿记录）；
  - 分析结果一致性（结果快照与当前规则集版本匹配）；
- 输出检查报告（通过项 / 告警项 / 失败项，含修复建议）。

#### F9 数据迁移
- 版本化迁移：`schema_migrations` 表记录已应用版本，启动时自动升级；
- 存储适配器：`memory`（内存，默认，测试友好）与 `sqlite`（持久化）；
- **数据导出 / 导入**：规则集、任务、结果整体打包为 JSON，可在不同环境之间搬迁；
- 命令行子命令：`migrate-up`、`export`、`import`。

### 4.2 扩展功能（扩写增值）

在基础功能之上，本期一并设计以下扩展能力，用于提升实用性与演示效果：

#### E1 变更影响分析（What-if）
- 对"候选规则集"（当前规则 + 模拟新增/删除/修改）做差异分析：
  - 新增规则会遮蔽哪些现有规则？
  - 删除规则会暴露哪些原本被遮蔽的流量？
  - 变更后覆盖度与冲突数的变化。
- 输出变更前后对比摘要，用于变更评审。

#### E2 风险评分
- 为每条规则计算风险分：动作（allow 加分）、通配范围（0.0.0.0/0、任意端口加分）、存在冲突/冗余扣分、缺少描述扣分；
- 规则集整体给出 0–100 健康分与分级（优/良/中/差）。

#### E3 规则分组（策略集）
- 规则归属 `policy_set`（如 `fw-office`、`sg-prod`、`acl-core`）；
- 所有分析均可限定在单个/多个策略集内进行，支持跨策略集对比。

#### E4 审计日志
- 记录关键操作：导入、删除、分析提交、导出、迁移；
- 字段：时间、操作人（`X-User`）、动作、对象、结果摘要；
- 提供最近 N 条查询接口，供前端"活动记录"面板展示。

#### E5 报告导出
- 分析结果可导出为 **JSON**（机器可读）与 **HTML 摘要**（人可读，含统计卡片与规则明细），HTML 由后端模板生成、前端可直接下载。

#### E6 模拟执行（仿真）
- 在纯内存中构建一份"影子规则集"，对任意场景执行可达性模拟，**不落库、不影响现有规则**，用于快速验证"这条新规则有没有用"。

## 5. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 1,000 条规则以内同步分析 < 1s；10,000 条规则矩阵分析走异步任务；导入 10,000 条 < 5s |
| 可迁移 | 所有数据可导出/导入；存储层可替换（内存 ↔ SQLite） |
| 可扩展 | 新增分析类型只需实现领域服务接口并注册；新增导入格式只需实现解析器接口 |
| 可靠性 | 任务失败可重试；服务重启后运行中任务标记为 `failed(interrupted)` 可重新提交 |
| 可维护性 | 分层清晰；领域层不依赖存储/API 细节；代码量受控（2000–2200 行） |
| 可观测性 | `/api/v1/health`、任务状态可查、审计日志可查 |
| 安全（基础） | 仅监听本地/内网地址；输入做长度与格式校验防注入；SQLite 使用参数化查询 |

## 6. 边界与非目标

- 不做真实网络探测（如 ICMP ping、端口扫描），可达性为**静态规则推演**；
- 不做设备配置下发（只分析、不改设备）；
- 不做多用户认证/权限（预留操作人记录）；
- 单机部署，不做分布式队列（Worker 为进程内池）；
- 规则匹配采用"优先级数值优先"语义（见 02 文档），不模拟设备厂商特有的顺序语义。
