## 4. 验收标准

1. `go build ./...` 与 `go vet ./...` 通过；
2. `go test ./... -race -count=1` 全绿；
3. 非测试 Go 代码行数 ∈ (2000, 2200)，代码文件数 ∈ (20, 25)（`find . -name '*.go' ! -name '*_test.go'` 统计校验）；
4. 端到端演示脚本通过：导入示例数据 → 四项分析 → 异步矩阵任务 → 完整检查 → 导出/导入迁移 → 前端界面各视图可用；
5. 完整检查报告无 fail 项（warn 仅限可解释项）；
6. 数据迁移双跑验证：memory 导出 → sqlite 导入 → 数据一致。

## 5. 行数控制的实施要点

- 每个文件按上表预算开发，**超过 ±15% 即重构**（抽取公共函数或压缩重复分支）；
- 避免过度泛化（不引入第三方库、不使用代码生成）；
- 注释以中文要点为主，不写重复注释（注释计入行数预算，控制在每文件 ≤ 10 行）；
- 空行不刻意凑数，以"每个功能块一个空行"的自然风格为准；
- 若最终行数不足 2000：在 handlers.go / reachability_service.go 补充更完整的矩阵分片与 whatif 说明性分支；若超出 2200：压缩 store.go 的样板与 dto 校验的重复分支。
