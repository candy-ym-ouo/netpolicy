# 07 前端界面设计

## 1. 设计原则

- **零构建**：原生 HTML + CSS + 原生 JS（ES6），由 Go 服务直接托管静态文件；
- **单页应用**：顶部导航切换视图，视图内容由 JS 渲染（`fetch` 调 API）；
- **移动端友好**：响应式栅格，表格横向滚动；
- **实时反馈**：任务类操作通过**轮询**展示进度，避免阻塞等待；
- 文件：`web/index.html`（结构）、`web/style.css`（样式）、`web/app.js`（逻辑）。

## 2. 页面结构与导航

```
┌────────────────────────────────────────────────────────────┐
│  NetPolicy Validator   [概览] [规则管理] [分析工作台] [可达性] [任务中心] [完整检查] │
├────────────────────────────────────────────────────────────┤
│                      视图内容（按导航切换）                      │
├────────────────────────────────────────────────────────────┤
│  footer：rulesetVersion · store 类型 · 最近审计日志摘要          │
└────────────────────────────────────────────────────────────┘
```

六个视图：

| 视图 | 关键内容 |
| --- | --- |
| 概览 Dashboard | 统计卡片（规则数、策略集数、待处理任务、健康分）、覆盖度进度条、最近审计日志、最近任务 |
| 规则管理 Rules | 导入区（格式/模式/文本域或文件上传）、筛选栏、规则表格（分页）、单条删除、导出按钮 |
| 分析工作台 Analysis | 分析类型选择（覆盖/冲突/冗余）、参数（策略集、目标空间）、提交 → 结果卡片 |
| 可达性 Reachability | 场景表单（源/目的/协议/端口）→ 结果（Verdict 徽章 + 命中规则链）；矩阵模式（多源多目标）异步 |
| 任务中心 Tasks | 任务表格（状态徽章、类型、时间、错误）、刷新/重试按钮、查看结果 |
| 完整检查 Checks | "运行检查"按钮 → 报告卡片（pass/warn/fail 统计 + 明细列表） |

## 3. 交互流程

### 3.1 规则导入

```
用户粘贴 JSON/CSV 或选择文件
  → 选择模式（追加/全量替换）
  → POST /rules/import
  → 成功：toast "导入 128 条"，刷新表格与概览
  → 失败：错误列表面板（行号 + 字段 + 原因），表格不刷新
```

### 3.2 同步分析（覆盖/冲突/冗余）

```
选择类型 → 可选填参数 → POST /analysis/{type}
  → 同步返回结果 → 渲染结果卡片
  → 若返回 TOO_MANY_RULES → 自动降级：改用 POST /analysis/tasks，进入轮询
```

### 3.3 异步任务轮询

```
提交 POST /analysis/tasks → 得到 taskId
  → 视图内启动 setInterval(1000ms)：GET /tasks/{id}
  → running：显示 spinner + 已运行时长
  → success：跳转/展开"查看结果"（GET /results/{id}，渲染 payload）
  → failed：红色徽章 + error 文案 + "重试"按钮（POST /tasks/{id}/retry）
  → 离开视图/切换导航时 clearInterval
```

### 3.4 结果渲染（示例）

- **覆盖结果**：覆盖度环形进度 + 未覆盖 CIDR 列表（红色标签）+ 分策略集条形图（CSS 宽度百分比）；
- **冲突结果**：冲突对表格（级别徽章：CRITICAL 红 / HIGH 橙 / MEDIUM 黄）+ 每条的建议文案；
- **冗余结果**：冗余规则表格（类型徽章：重复/遮蔽/泛化）+ 冗余率统计；
- **可达性结果**：`allow` 绿徽章 / `deny` 红徽章 / `default` 灰徽章 + 命中规则链（按优先级排列的卡片列表）。

## 4. 与 API 的对接映射

| 前端动作 | API |
| --- | --- |
| 加载概览 | `GET /stats`、`GET /audit?limit=8` |
| 导入规则 | `POST /rules/import` |
| 列表/筛选/分页 | `GET /rules?policySet=&action=&q=&page=&pageSize=` |
| 删除规则 | `DELETE /rules/{id}` |
| 导出规则 | `GET /rules/export`（下载 JSON） |
| 同步分析 | `POST /analysis/{coverage|conflicts|redundancy}` |
| 可达性查询 | `POST /analysis/reachability` |
| 矩阵分析 | `POST /analysis/tasks {type:"matrix", ...}` |
| 任务列表/详情 | `GET /analysis/tasks`、`GET /analysis/tasks/{id}` |
| 任务重试 | `POST /analysis/tasks/{id}/retry` |
| 结果查看 | `GET /analysis/results/{id}` |
| 完整检查 | `GET /checks`、`GET /checks/latest` |
| 数据迁移 | `GET /migrate/export`（下载）、`POST /migrate/import`（上传） |
| 报告下载 | `GET /reports/{taskId}?format=html` |

> 前端所有请求统一携带 `X-User: web-demo` 头，便于审计日志记录操作来源。

## 5. 视觉规范（简）

- 主色：`#2563eb`（蓝），危险 `#dc2626`，成功 `#16a34a`，警告 `#d97706`；
- 状态徽章：pending 灰、running 蓝（spinner）、success 绿、failed 红、canceled 灰；
- 表格行 hover 高亮；长文本（CIDR 列表）使用等宽字体 `ui-monospace`；
- 全部组件不依赖任何外部 CDN（离线可用）。

## 6. 文件职责（web/）

| 文件 | 职责 | 预计规模 |
| --- | --- | --- |
