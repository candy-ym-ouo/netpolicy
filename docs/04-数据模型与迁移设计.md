# 04 数据模型与迁移设计

## 1. 实体总览

```
┌──────────────┐     ┌──────────────────┐     ┌──────────────────┐
│   rule       │     │  analysis_task   │     │ analysis_result  │
│  (规则)       │     │  (分析任务)       │     │  (分析结果)       │
│  policy_set  │     │  type/status/... │     │  task_id 1:1     │
│  src/dst/... │     │  params(JSON)    │◀────│  payload(JSON)   │
└──────────────┘     └──────────────────┘     └──────────────────┘
       1  N                      1                1
       │                        │                │
       └──────────┬─────────────┴────────────────┘
                  ▼
        ┌──────────────────┐     ┌──────────────────┐
        │   audit_log      │     │ schema_migrations│
        │  (审计日志)       │     │  (迁移版本)       │
        └──────────────────┘     └──────────────────┘
```

- **rule**：导入的访问规则（核心实体）；
- **analysis_task**：异步分析任务（含同步分析的可选落库）；`ruleset_version` 记录提交时规则集版本；
- **analysis_result**：任务结果，`payload` 按任务类型存放不同结构（覆盖统计/冲突列表/冗余列表/可达性场景集）；
- **audit_log**：操作审计（导入、删除、分析、导出、迁移）；
- **schema_migrations**：迁移版本表（SQLite 持久化时使用；内存存储中迁移为空操作但保留版本号概念，保证两种存储行为一致）。

## 2. 逻辑模型（Go 结构对应 domain/model）

```go
type Rule struct {
    ID          string    `json:"id"`
    PolicySet   string    `json:"policySet"`
    Priority    int       `json:"priority"`
    Action      string    `json:"action"`       // allow | deny
    Src         string    `json:"src"`          // CIDR
    Dst         string    `json:"dst"`          // CIDR
    Protocol    string    `json:"protocol"`     // tcp|udp|icmp|any
    PortFrom    int       `json:"portFrom"`     // 1-65535
    PortTo      int       `json:"portTo"`
    Description string    `json:"description"`
    Source      string    `json:"source"`
    CreatedAt   time.Time `json:"createdAt"`
    UpdatedAt   time.Time `json:"updatedAt"`
}

type AnalysisTask struct {
    ID              string    `json:"id"`
    Type            string    `json:"type"`    // coverage|conflicts|redundancy|reachability|matrix|whatif|simulate
    Status          string    `json:"status"`  // pending|running|success|failed|canceled
    Params          string    `json:"params"`  // JSON 序列化参数
    RulesetVersion  int       `json:"rulesetVersion"`
    RetryCount      int       `json:"retryCount"`
    Error           string    `json:"error,omitempty"`
    CreatedAt       time.Time `json:"createdAt"`
    StartedAt       *time.Time `json:"startedAt,omitempty"`
    FinishedAt      *time.Time `json:"finishedAt,omitempty"`
}

type AnalysisResult struct {
    TaskID          string    `json:"taskId"`
    Type            string    `json:"type"`
    RulesetVersion  int       `json:"rulesetVersion"`
    Summary         string    `json:"summary"`  // 人读摘要，如 "覆盖度 87.5%，未覆盖 12 个 CIDR 块"
    Payload         string    `json:"payload"`  // JSON 结构化结果
    CreatedAt       time.Time `json:"createdAt"`
}

type AuditLog struct {
    ID        int64     `json:"id"`
    At        time.Time `json:"at"`
    User      string    `json:"user"`     // 取自 X-User 头
    Action    string    `json:"action"`   // import|delete|analyze|export|migrate|check
    Target    string    `json:"target"`
    Detail    string    `json:"detail"`
}
```

## 3. SQLite 表结构（DDL 草案，由迁移脚本执行）

```sql
-- 版本 1：基础表
CREATE TABLE IF NOT EXISTS rules (
    id          TEXT PRIMARY KEY,
    policy_set  TEXT NOT NULL DEFAULT 'default',
    priority    INTEGER NOT NULL DEFAULT 100,
    action      TEXT NOT NULL CHECK (action IN ('allow','deny')),
    src         TEXT NOT NULL,
    dst         TEXT NOT NULL,
    protocol    TEXT NOT NULL DEFAULT 'any' CHECK (protocol IN ('tcp','udp','icmp','any')),
    port_from   INTEGER NOT NULL DEFAULT 1,
    port_to     INTEGER NOT NULL DEFAULT 65535,
    description TEXT NOT NULL DEFAULT '',
    source      TEXT NOT NULL DEFAULT '',
    created_at  TEXT NOT NULL,
    updated_at  TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_rules_policy ON rules(policy_set);
CREATE INDEX IF NOT EXISTS idx_rules_action ON rules(action);

CREATE TABLE IF NOT EXISTS analysis_task (
    id               TEXT PRIMARY KEY,
    type             TEXT NOT NULL,
    status           TEXT NOT NULL,
    params           TEXT NOT NULL,
    ruleset_version  INTEGER NOT NULL DEFAULT 0,
    retry_count      INTEGER NOT NULL DEFAULT 0,
    error            TEXT NOT NULL DEFAULT '',
    created_at       TEXT NOT NULL,
    started_at       TEXT,
    finished_at      TEXT
);
CREATE INDEX IF NOT EXISTS idx_task_status ON analysis_task(status);

CREATE TABLE IF NOT EXISTS analysis_result (
    task_id          TEXT PRIMARY KEY,
    type             TEXT NOT NULL,
    ruleset_version  INTEGER NOT NULL DEFAULT 0,
    summary          TEXT NOT NULL,
    payload          TEXT NOT NULL,
    created_at       TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS audit_log (
    id      INTEGER PRIMARY KEY AUTOINCREMENT,
    at      TEXT NOT NULL,
    user    TEXT NOT NULL DEFAULT '',
    action  TEXT NOT NULL,
    target  TEXT NOT NULL DEFAULT '',
    detail  TEXT NOT NULL DEFAULT ''
);

CREATE TABLE IF NOT EXISTS schema_migrations (
    version     INTEGER PRIMARY KEY,
    applied_at  TEXT NOT NULL
);
```

> 内存存储（MemoryStore）不执行真实 SQL，但对外暴露**完全一致的 Repository 语义**，并通过 `ReplaceAllRules` 使版本号递增逻辑一致，保证"数据可迁移"不依赖具体存储。

## 4. 迁移机制设计

### 4.1 版本化迁移（Migrator）

- 迁移定义为一个有序数组：`[]Migration{Version: 1, Name: "init", DDL: "..."}`；
- 执行流程：
  1. 读取 `schema_migrations` 获得已应用的最大版本 `current`；
  2. 遍历迁移定义，对 `version > current` 的项：在**事务**中执行 DDL，写入版本记录；
  3. 任一迁移失败 → 回滚该版本事务、中止启动并报错（启动自检失败）；
- 内存存储：`ApplyMigration` 为空实现，但 `MigrationVersion` 返回定义的最大版本（视为已最新），保证行为一致；
- 新增字段/表只允许**追加新版本号**的迁移，禁止修改历史迁移。

### 4.2 数据可迁移（导出 / 导入）

**导出包结构**（JSON，单一文件）：

```json
{
  "schemaVersion": 1,
  "exportedAt": "2026-01-01T00:00:00Z",
  "rulesetVersion": 7,
  "rules": [ /* Rule 列表 */ ],
  "tasks": [ /* AnalysisTask 列表 */ ],
  "results": [ /* AnalysisResult 列表 */ ]
}
```

**导入流程**：
1. 校验 `schemaVersion` 兼容（等于或低于当前支持版本）；
2. 校验每条 Rule 通过解析层的格式校验（复用 `parser.Validation`）；
3. 以**全量替换**方式写入（`ReplaceAllRules`），同时导入任务/结果（按 taskId 去重）；
4. 更新 `ruleset_version` 为导出值；
5. 写审计日志 `migrate`；
6. 全程事务性：任一校验失败则整体失败，不产生部分写入。

**触发方式**：
- 命令行：`netpolicy export -o backup.json`、`netpolicy import -i backup.json`（需 `--store sqlite` 或内存均可）；
- API：`GET /api/v1/migrate/export`、`POST /api/v1/migrate/import`。

**典型迁移场景**：
- 开发环境（memory）→ 测试环境（sqlite）：导出 → 启动目标实例 → 导入；
- SQLite 文件整体拷贝 + 迁移自动升级（版本 1 → 2）；
- 演示环境初始化：`import` 预置示例规则集。

## 5. 数据一致性约束

| 约束 | 实现 |
| --- | --- |
| 规则 ID 唯一 | SQLite 主键 / 内存 map 键；导入重复 ID 时报错（除非 replace 模式整体覆盖） |
| 任务状态合法 | 状态机在 worker.Manager 中集中控制，禁止外部直接改状态 |
| 结果必须绑定任务 | `analysis_result.task_id` 外键语义（SQLite 开启外键或由代码保证） |
| ruleset_version 单调递增 | 仅在 `ReplaceAllRules` / `SaveRules` 成功后 +1，内存与 SQLite 同逻辑 |
| 审计日志只追加 | 无更新/删除接口 |
| 引用完整性 | 完整检查（check.Checker）扫描孤儿任务/结果/规则引用 |

## 6. 存储实现选型与切换

| 维度 | MemoryStore | SQLiteStore |
| --- | --- | --- |
| 用途 | 默认、演示、单元测试 | 生产/持久化 |
| 并发 | 全局 `sync.RWMutex` 保护 map | 单写多读，`modernc.org/sqlite` 连接池（默认 1 写连接） |
| 迁移 | 空操作 | 版本化 DDL |
| 数据恢复 | 无 | 文件持久化 |
| 切换方式 | `-store memory`（默认） | `-store sqlite -db ./data.db` |

**统一接口保证**：两个实现都满足 `storage.Repository` 接口，装配时由 `main` 根据配置选择；领域层与 API 层不感知具体实现。
