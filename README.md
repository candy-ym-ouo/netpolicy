# NetPolicy Validator — 网络策略验证器

> 用 Go 构建的网络策略验证器：导入访问规则后识别**覆盖（Coverage）**、**冲突（Conflict）**、**冗余（Redundancy）**与**目标可达性（Reachability）**，按**解析、领域、存储**分层，数据可迁移，包含 **API、后台计算、测试及完整检查**。

## 项目定位

企业网络中防火墙、安全组、ACL（访问控制列表）等设备上的访问规则通常存在**数量庞大、手工维护、跨设备不一致**的问题。本系统将分散的访问规则集中导入、统一建模，通过四类分析能力为网络运维人员回答四个核心问题：

| 分析能力 | 回答的问题 | 典型场景 |
| --- | --- | --- |
| 覆盖分析 Coverage | 现有规则是否覆盖了全部应管控的流量？哪些区域没有规则？ | 新业务上线前的空白区域排查 |
| 冲突检测 Conflict | 规则之间是否存在互相矛盾的定义？ | 安全组规则与防火墙规则互相"打架" |
| 冗余检测 Redundancy | 哪些规则是多余、可删除的？ | 规则瘦身、合规审计（"最小权限"） |
| 可达性分析 Reachability | 指定源能否到达指定目标？经过哪些规则？ | 故障排查、变更前影响评估 |

## 核心特性

- **多格式规则导入**：支持 CSV / JSON / YAML 三种格式，自动探测格式并校验。
- **四维分析引擎**：覆盖、冲突、冗余、可达性四大分析服务，支持批量与单场景。
- **分层架构**：解析层（Parser）→ 领域层（Domain）→ 存储层（Storage），依赖方向自上而下，领域层面向接口编程，存储可替换。
- **数据可迁移**：内置版本化迁移（Migration），支持内存存储 / SQLite 存储两种实现，规则集与任务结果可导出 / 导入（JSON），实现环境间数据搬迁。
- **API 服务**：RESTful HTTP API，统一 JSON 出入参、错误码、分页与过滤。
- **后台计算**：重计算（大规则集分析、批量可达性矩阵）异步化，任务状态机 + Worker 池 + 状态持久化，前端轮询取结果。
- **完整检查**：启动自检 + 按需检查 + 完整性报告（规则格式、引用完整性、数据一致性、分析结果一致性）。
- **简单前端**：原生 HTML/CSS/JS 单页应用，无需构建工具，覆盖概览、规则管理、分析工作台、可达性查询与任务中心。

## 快速开始（规划）

```bash
# 1. 构建
go build -o netpolicy ./cmd/server

# 2. 启动（默认端口 8080，内存存储；可通过配置切换 SQLite）
./netpolicy -addr :8080 -store memory

# 3. 导入规则（示例数据见 docs/05 附录）
curl -X POST http://localhost:8080/api/v1/rules/import \
  -H "Content-Type: application/json" \
  -d '{"format":"json","data":"[{\"id\":\"r1\",\"src\":\"10.0.0.0/24\",...}]"}'

# 4. 提交分析任务
curl -X POST http://localhost:8080/api/v1/analysis/tasks \
  -d '{"type":"coverage","ruleIds":["r1","r2"]}'

# 5. 查询任务与结果
curl http://localhost:8080/api/v1/analysis/tasks/{taskId}
curl http://localhost:8080/api/v1/analysis/results/{taskId}

# 6. 打开前端
open http://localhost:8080
```

## 工程约束

- 语言：Go（目标版本 1.22+，仅标准库 + `modernc.org/sqlite` 纯 Go 驱动）。
- 代码规模（不含测试）：**Go 代码 2000–2200 行**，代码文件 **20–25 个**（规划为 21 个 Go 文件 + 3 个前端文件）。
- 数据迁移：版本化迁移表 + 导出/导入命令，保证数据可在不同部署环境间迁移。
- 分层约束：领域层不感知存储与 API 细节；存储层通过接口注入；后台任务与 API 通过领域服务衔接。
